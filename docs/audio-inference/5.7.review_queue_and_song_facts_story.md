# Story 5.7 — Machine Review Queue and Human Song Facts (v2.1)

## Goal

Give a human a cheap way to answer the few questions the machine genuinely
cannot settle, and give the machine a place to ask them. Where the pipeline is
uncertain, a short human answer is worth more than any amount of additional
inference.

## Two files and a strict direction of flow

### Human input — `reference/human/song_facts.json` (new)

Song-level, untimed truths a person can state directly: `genre`, `form_family`,
and later any other whole-song fact. Shape:

```json
{
  "schema_version": "1.1",
  "song_name": "Armin - Revolution",
  "facts": {
    "form_family": { "value": "dance_form", "provenance": "human-confirmed", "confirmed_on": "2026-08-30" },
    "has_drop":     { "value": true,        "provenance": "human-confirmed" }
  }
}
```

Each value carries `provenance: "human-confirmed"`. This is a **sibling** of
`human_hints.json`, not part of it: every `human_hints.json` entry is a timed
moment consumed by event benchmarking and ML training, whereas song facts are
untimed, have a different lifecycle, and a different consumer.

### Machine output — `artifacts/validation/review_queue.json` (new)

The open questions this run could not settle, ranked so the highest-leverage
question is first. Each entry: the `field` in question, its competing
`candidates` with scores, `evidence_timestamps` of the ambiguous evidence, and
`reason_low_confidence`. Question sources in v2.1:

- `form_family` when inferred confidence < 0.55 (or `unknown`) and not already
  human-confirmed — candidates `dance_form` / `song_form` / `hybrid` with their
  audio-evidence scores.
- `form_family_vs_genre` — the item 1a disagreement flag: the inferred
  `form_family` conflicts with the genre label. A human-confirmed genre would
  break the tie.
- `sections.<id>.form_role` when the role is `unknown` or its best-vs-second
  margin is below 0.12.
- `drops.timed_location` when `song_facts.has_drop` is true but the pipeline
  detected no drop.

## Direction of flow

The analyzer proposes into `validation/`; a human disposes into `reference/`.
**The analyzer never writes into `reference/`.** `reference/` is the validation
truth set; if the analyzer seeded its own low-confidence guesses there,
validation would score inference against a file inference wrote. Under this
split, an unanswered question is unambiguously not in use, and the
constitution's rule holds: `reference/human/` is written only by the UI on an
explicit human save (Story 5.2 / 8.8).

## Use

A human-confirmed `form_family` breaks a tie in the segmenter's `form_family`
inference only when the measured evidence is weak (confidence < 0.55); it never
overrides a confident measurement. Where a human fact is used, the affected
output records `provenance: "human-confirmed"`.

## Acceptance Criteria

- A run on a song with ambiguous form emits a ranked queue whose top entry is
  answerable in one choice.
- Answering it in `song_facts.json` changes the next run's `form_family`, and the
  resulting sections carry `provenance: "human-confirmed"`.
- `reference/` receives no analyzer writes (regression test:
  `tests/test_review_queue.py::test_analyzer_never_writes_reference`).
