# EPIC 8 - Story 8.1

## Song Auto-Discovery and Artifact Entry

## Goal

Allow the internal debugger to discover available per-song artifact directories automatically so users do not need to type song folder names manually.

## Inputs

- `data/analysis/<Song - Artist>/artifacts/`
- `data/analysis/<Song - Artist>/` as optional helper context

## Processing Steps

1. Discover per-song directories directly from `data/analysis/`.
2. Present those directories as selectable debugger entries.
3. Initialize debugger loading from a selected discovered song directory.
4. Preserve read-only access to all mounted generated-data paths.

## Output

- browser-only song selection and discovery state inside the debugger

## Acceptance Criteria

- Users can choose a discovered song directory without typing it manually.
- Song discovery reads the mounted artifact tree directly.
- Discovery state remains browser-local and read-only.
- No debugger-generated files are written into `data/analysis/`.

## UI v2 component map (plan item 10)

The React + TypeScript rebuild (`docs/web-ui/ui-rebuild/`) implements this story in:

- `ui/src/data/discovery.ts` — `data/analysis` ∩ `data/songs` intersection + `discoverSongs()`.
- `ui/src/data/useSong.ts` — per-artifact `{ status, data, error }` loader hook.
- `ui/src/app/loadStates.ts` — `selectSongListState` (loading / error / empty / ready) and `selectSongLoadState` (loading / fatal / degraded / ready) — pure, unit-tested.
- `ui/src/App.tsx` — `SongPicker` drawer view renders the four list states.
