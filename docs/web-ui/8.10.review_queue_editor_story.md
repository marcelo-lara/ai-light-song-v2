# Story 8.10 — Review Queue Editor (v1.1)

## Goal

Close the item 7 round-trip: render `artifacts/validation/review_queue.json` in
the debugger as answerable questions, and save the answers into
`reference/human/song_facts.json`. Without this, the queue has no consumer and
human song facts have no editor.

## Scope

- **In:** a Review Queue panel that lists the run's open questions, lets a human
  pick an answer for the whole-song questions (`form_family`,
  `form_family_vs_genre`), and saves them to `song_facts.json` on an explicit
  Save. Per-section `form_role` and `drops.timed_location` questions are shown
  for context only — they are answered by editing `human_hints.json` (Story 8.8).
- **Out:** lane rendering of composite phases and the new section fields
  (follows once the artifact shapes settle — v1.2).

## Behaviour

- The panel sits inside the existing Human Hint editor sidebar and is bound to
  the selected song.
- It fetches `review_queue.json` (per-song, produced by pipeline stage 5.1) and
  the current `song_facts.json` (to show what is already answered).
- Each question shows its `field`, `reason_low_confidence`, and any
  `evidence_timestamps`. Answerable questions render a `<select>` populated from
  the question's `candidates` (value + score).
- **Save** issues `PUT /api/song-facts/<song>` with `{ song_name, facts }`. The
  dev-server handler (`vite.config.js`) normalises each fact to
  `{ value, provenance: "human-confirmed", confirmed_on }` and writes
  `data/analysis/<song>/reference/human/song_facts.json`. This is the **only**
  writer of that file — the same rule Story 8.8 applies to human hints; the
  analyzer never writes `reference/`.

## Acceptance Criteria

- Answering `form_family` in the panel and saving writes
  `song_facts.json` with `provenance: "human-confirmed"`.
- The next analyzer run reads that file, and — when the measured evidence is weak
  — the resulting sections carry `provenance: "human-confirmed"` (item 2.1).
- No path other than an explicit human Save writes `song_facts.json`.

## Files (UI v2 — React + TypeScript rebuild)

- `ui/vite.config.ts` — `PUT /api/song-facts/<song>` handler + `songFactsFilePath`
  (merge-not-rewrite; see D4 in the implementation plan).
- `ui/src/data/saveSongFacts.ts` — `buildSongFactsPayload` + `saveSongFacts` client.
- `ui/src/panel/reviewQueue.ts` — `partitionReviewQueue` / `questionOptions` (pure, unit-tested).
- `ui/src/panel/ReviewQueuePanel.tsx` — the right-panel third mode, opened from the

  when a song has no `review_queue.json`.
- `ui/src/panel/RightPanel.tsx` — the shell (mode switch, `esc` / outside-click
  dismiss, focus trap + restore-on-close from plan item 10).
